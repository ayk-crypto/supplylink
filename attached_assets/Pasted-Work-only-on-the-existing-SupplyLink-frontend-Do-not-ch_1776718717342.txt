Goal:
Implement Module 20AL Frontend: Route Templates and Template-Based Route Generation.

Context:
Backend now supports route templates, template stops, and generation of normal routes from templates.

Available backend endpoints:
- GET /api/v1/route-templates
- POST /api/v1/route-templates
- GET /api/v1/route-templates/:templateId
- PATCH /api/v1/route-templates/:templateId
- DELETE /api/v1/route-templates/:templateId
- GET /api/v1/route-templates/:templateId/stops
- POST /api/v1/route-templates/:templateId/stops
- PATCH /api/v1/route-templates/:templateId/stops/:stopId
- DELETE /api/v1/route-templates/:templateId/stops/:stopId
- POST /api/v1/route-templates/:templateId/generate

Backend behavior:
- route template = reusable recurring plan
- route = dated execution instance
- generated routes remain editable through existing /routes flows
- template edits do not change already-generated routes
- recurrenceType currently supports only weekly
- recurrenceDays supports multiple weekdays as 0-6
- generated routes may include sourceRouteTemplateId

Core objective:
Add a frontend Route Templates experience so vendors can manage recurring route plans and generate dated route instances from them, without redesigning the app or changing backend APIs.
