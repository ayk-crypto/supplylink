Goal:
Implement Module 20AP: Real-World Refinement Batch (Wording, Readability, Status UX, and Layout Polish).

Context:
SupplyLink is now operationally complete for Phase 1. Manual testing surfaced a number of real-world usability issues across customer, category, product, quotation, order, invoice, inventory, route, ledger, audit, and settings screens.

Core objective:
Fix the most visible and practical UX/readability/layout issues found during real usage, without redesigning the system or changing backend APIs.

Important:
This module is a refinement/polish pass based on observed pain points.
Do not introduce new backend dependencies.
Do not add major new features.
Keep changes additive, clean, and production-minded.

What to do:

1) Business-friendly wording cleanup
Review high-visibility page titles, subtitles, hints, and empty-state copy.
Replace internal/technical wording with vendor-facing business language.

Examples of the kind of cleanup needed:
- customer page subtitle currently sounds internal/technical; rewrite it to feel like a page for a vendor managing their own customers
- category page subtitle should also sound vendor-facing and business-friendly
- ensure capitalization is proper in titles, labels, and section text

Do this carefully across the app where wording clearly feels internal, awkward, or overly technical.

2) Status badge consistency
Across major screens (customers, quotations, orders, invoices, routes, inventory where relevant):
- normalize status text to human-friendly casing (e.g. Draft, Confirmed, Active)
- replace inconsistent lowercase/all-caps rendering
- apply clear color-coded status treatment where practical and already consistent with existing styling patterns
- improve readability without redesigning the whole visual system

This includes places like:
- customer relationship status
- quotation/order/invoice status
- route status
- any obvious operational status labels that currently look inconsistent

3) Human-readable dates
Audit major user-facing dates/timestamps and improve readability using existing date formatting helpers where practical.

Focus especially on:
- quotation detail dates
- order detail dates
- invoice detail dates
- route/detail dates
- audit timestamps if still awkward
- any obvious raw/non-human-friendly date renderings found in testing

Target output should feel business-friendly, such as:
- 12 Mar 2026
- 12 Mar 2026, 2:30 PM

Keep changes safe and centralized where possible.

4) Customer screen and customer detail polish
Fix the issues observed on customer pages:

Customers list:
- rename “Customer Page” style wording into a stronger business-facing “Customer Directory” / similar if appropriate
- ensure search controls look like search controls, not like an input/button confusion
- keep add/edit flows intact

Customer detail:
- improve responsiveness/layout for long email and other long fields
- make relationship status visually clearer (e.g. Active with color)
- improve layout so it feels less brittle on narrower widths
- replace confusing “Sample” wording on metrics with more understandable language, or remove the label if a clearer phrasing is better

Audit link flow:
- where “Full Audit” currently shows random/poor entity naming, improve displayed naming/labeling on the frontend side if feasible from current data already available

5) Categories / Products / Forms polish
Fix the rough layout/readability issues in:
- category form
- product form
- similar create/edit forms where the same awkwardness appears

Improvements should include:
- better spacing/alignment
- clearer section/title capitalization
- vendor-facing subtitle wording
- consistent field rhythm
- better treatment of autogenerated-looking fields if already displayed in UI

Do not add backend features yet for SKU/account-code generation in this module.

6) Search controls polish
Across list screens where search was flagged as visually awkward:
- improve search field/button visual distinction
- ensure button does not look like a text field

- focus on layout and clarity, not feature redesign
